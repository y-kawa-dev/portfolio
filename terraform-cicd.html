制作の経緯

AI家計簿アプリを開発した後、「手作業に頼らないモダンなインフラ管理手法（IaC）」の習得を目的に取り組みました。 Terraformを使いAWSリソースをコード化することで、環境の再現性・変更履歴の管理を実現。 さらにGitHub Actionsと組み合わせることで、コードをpushするだけで自動的にAWS上へデプロイされるパイプラインを構築しました。

OIDC認証について： 通常のCI/CDでは「AWSへのアクセスキー」をGitHubに保存する必要がありますが、OIDCを使うことでキーを持たずに一時的な認証が可能になります。キーの漏洩リスクをなくせるセキュアな方法です。

3 技術的なポイント

IaC による再現性

VPC・セキュリティグループ・ECS・ECR・IAMなど、すべてのAWSリソースを Terraformコードで定義。コマンド一つで同じ環境を何度でも再構築できます。 環境の変更もコードで管理するため、変更履歴が残ります。

State 管理（S3 + DynamoDB）

Terraformは「現在のインフラ状態」を記録したStateファイルを使い差分管理します。 このファイルをS3に保存し、DynamoDBで排他ロックをかけることで、 複数人が同時に操作しても壊れない構成にしています。

OIDC によるキーレス認証

GitHub ActionsからAWSへの接続にOIDC（OpenID Connect）を採用。 長期的なアクセスキーをGitHubに保存せず、実行時だけ一時的な認証を行います。 特定リポジトリからのアクセスのみ許可するよう制限しています。

セキュリティの改善履歴

初回実装後にセキュリティを見直し、IAMロールを最小権限に絞り直しました（PR #1）。 また、ハードコードされていたパスワードを環境変数化し、 ECRの脆弱性スキャンも有効化するよう改善しています。

まとめ：習得した知見

このプロジェクトを通じて、アプリを作る（開発）だけでなく、適切に動かす（インフラ・デプロイ）ための知識を習得しました。

Terraformによって「インフラもコードで管理する」という考え方を実践し、GitHub Actionsによって「手動デプロイをなくす」という体験ができました。 セキュリティ面でも、最初の実装から改善を重ねる過程で、最小権限の原則やキーレス認証の重要性を実感しています。
